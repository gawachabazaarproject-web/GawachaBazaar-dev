# Gawacha Bazaar Database Specification: Version 1

This document defines the authoritative database specification for the **Gawacha Bazaar** platform.

---

## Global Architectural Conventions

1. **Primary Keys**:
   - Every table uses `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
   - Sequential 64-bit integer IDs ensure optimal B-Tree performance, indexing density, and foreign key join speed in PostgreSQL.
2. **Timestamps**:
   - All timestamp columns use `TIMESTAMPTZ` (timestamp with time zone).
   - Columns:
     - `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
     - `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
   - `DEFAULT now()` initializes timestamps upon record creation. Application/ORM layers manage `updated_at` on record modification (`onupdate=func.now()`). No database triggers are introduced.
3. **Naming Standards**:
   - PostgreSQL identifier casing: `snake_case`.
   - Table names: Plural nouns (`roles`, `users`, `user_roles`, `addresses`).
   - Foreign key columns: `<singular_entity>_id` (e.g., `user_id`, `role_id`).
   - Constraints & Indexes:
     - Primary key: `pk_<table_name>`
     - Foreign key: `fk_<table_name>_<column_name>_<target_table>`
     - Unique constraint: `uq_<table_name>_<column_names>`
     - Index: `ix_<table_name>_<column_names>`
4. **Data Integrity & Invariants**:
   - Invariants are enforced strictly at the PostgreSQL database engine level via constraints, foreign keys, and partial unique indexes.
   - Plaintext passwords are NEVER stored in the database.
5. **Testing Strategy**:
   - Integration tests execute against an isolated test database (`gawachabazaar_test`).
   - The primary development database (`gawachabazaar`) is never subjected to destructive test operations.

Domain 1 encompasses user account records, role definitions, multi-role assignments, and shipping/billing delivery addresses.

### Table 1: `roles`

#### Purpose
Defines distinct functional roles and access capabilities within the platform. Roles are reference business data assigned to users. Initial conceptual roles include `CUSTOMER`, `FARMER`, `SUPPLIER`, `DELIVERY_PARTNER`, and `ADMIN`. Roles are not hardcoded as an enum type to allow organizational growth.

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `name` | `VARCHAR(50)` | No | None | Unique role name (e.g. `CUSTOMER`, `FARMER`) |
| `description` | `VARCHAR(255)` | Yes | `NULL` | Optional functional description of the role |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | Record modification timestamp |

#### Constraints & Indexes
- **Primary Key**: `pk_roles` on `(id)`
- **Unique Constraint**: `uq_roles_name` on `(name)`
- **Index**: Unique index automatically created on `name` by PostgreSQL

#### Relationships
- `Role 1:N UserRole`: Referenced by `user_roles.role_id`

### Table 2: `users`

#### Purpose
Represents individual account identities (customers, farmers, suppliers, delivery partners, and administrators). Role assignment is deliberately decoupled from this table.

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `name` | `VARCHAR(150)` | No | None | Full legal or display name |
| `email` | `VARCHAR(255)` | No | None | Unique email address for login and notifications |
| `phone` | `VARCHAR(20)` | No | None | Unique mobile telephone number |
| `password_hash` | `TEXT` | No | None | Cryptographic password hash (Argon2id) |
| `status` | `VARCHAR(30)` | No | `'ACTIVE'` | Account status |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | Record modification timestamp |

#### Constraints & Indexes
- **Primary Key**: `pk_users` on `(id)`
- **Unique Constraint**: `uq_users_email` on `(email)`
- **Unique Constraint**: `uq_users_phone` on `(phone)`
- **Check Constraint**: `ck_users_status` enforcing `status IN ('ACTIVE', 'INACTIVE', 'SUSPENDED')`
- **Indexes**:
  - `ix_users_email` via unique constraint
  - `ix_users_phone` via unique constraint

#### Key Business Invariant
- `users` does **NOT** contain `role_id`. All role assignments reside strictly in `user_roles`.

### Table 3: `user_roles`

#### Purpose
Junction table managing many-to-many relationships between `users` and `roles`. Allows a single user to act in multiple capacities (e.g., both `CUSTOMER` and `FARMER`) while designating an optional primary role context.

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `user_id` | `BIGINT` | No | None | Foreign key referencing `users.id` |
| `role_id` | `BIGINT` | No | None | Foreign key referencing `roles.id` |
| `is_primary` | `BOOLEAN` | No | `false` | Indicates whether this is the user's primary/default role |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | Record modification timestamp |

#### Foreign Keys & Delete Behaviors
- `fk_user_roles_user_id`: References `users.id` with `ON DELETE CASCADE` (deleting a user removes their role assignments).
- `fk_user_roles_role_id`: References `roles.id` with `ON DELETE RESTRICT` (a role cannot be deleted while assigned to any user).

#### Constraints & Indexes
- **Primary Key**: `pk_user_roles` on `(id)`
- **Unique Constraint**: `uq_user_roles_user_role` on `(user_id, role_id)` — prevents duplicate assignments of the same role to a user.
- **Partial Unique Index**:
  ```sql
  CREATE UNIQUE INDEX uq_user_roles_user_primary ON user_roles (user_id) WHERE is_primary = TRUE;
  ```
  **Business Invariant**: Enforces at the database engine level that a user may have **at most one** primary role (`is_primary = true`).
- **Foreign Key Index**: `ix_user_roles_role_id` on `(role_id)` to optimize join performance when querying users by role.

### Table 4: `addresses`

#### Purpose
Stores physical delivery and pickup addresses for users (residential, farm locations, warehouses).

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `user_id` | `BIGINT` | No | None | Foreign key referencing `users.id` |
| `label` | `VARCHAR(50)` | No | None | Address label (e.g., `Home`, `Work`, `Farm Location`) |
| `address_line_1` | `VARCHAR(255)` | No | None | Street address, building number, road |
| `address_line_2` | `VARCHAR(255)` | Yes | `NULL` | Apartment, suite, unit, landmark |
| `city` | `VARCHAR(100)` | No | None | City / Municipality |
| `state` | `VARCHAR(100)` | No | None | State / Province |
| `postal_code` | `VARCHAR(20)` | No | None | Postal / PIN / ZIP code |
| `latitude` | `NUMERIC(9,6)` | Yes | `NULL` | Geographic latitude coordinate |
| `longitude` | `NUMERIC(9,6)` | Yes | `NULL` | Geographic longitude coordinate |
| `is_default` | `BOOLEAN` | No | `false` | Flag indicating default delivery address |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | Record modification timestamp |

#### Foreign Keys & Delete Behaviors
- `fk_addresses_user_id`: References `users.id` with `ON DELETE CASCADE` (deleting a user removes associated address entries).

#### Constraints & Indexes
- **Primary Key**: `pk_addresses` on `(id)`
- **Partial Unique Index**:
  ```sql
  CREATE UNIQUE INDEX uq_addresses_user_default ON addresses (user_id) WHERE is_default = TRUE;
  ```
  **Business Invariant**: Enforces at the database engine level that a user may have **at most one** default address (`is_default = true`).
- **Index**: `ix_addresses_user_id` on `(user_id)` for rapid lookup of all addresses belonging to a user.
