# Gawacha Bazaar Database Specification: Version 2 — Farm & Traceability

This document defines the database architecture and technical specifications for **Phase 2: Farm & Traceability** of the Gawacha Bazaar platform.

---

## 1. Business Context & Physical Process Flow

Gawacha Bazaar is a genuine farm-to-home marketplace. The produce lifecycle moves through the following stages:

```text
Village Farm (Source)
      ↓
   Harvest
      ↓
  Collection
      ↓
Sorting & Grading
      ↓
Gawacha Bazaar Hub
      ↓
 Preparation
      ↓
  Delivery
      ↓
Customer Home
```

### Architectural Responsibilities in Phase 2
1. **Establish Provenance**: Record exactly where produce was grown (specific farm, village, district, coordinates, and farmer owner).
2. **Batch-Level Traceability**: Maintain distinct harvest batches with metrics (harvest date, shelf-life expiry, quantity, unit of measurement, and lifecycle status).
3. **Quality & Inspection Audit Trail**: Record all point-in-time quality inspections performed on batches, the inspecting user, timestamps, and pass/fail statuses.

---

## 2. Key Domain Boundary Decisions

- **Direct Farm Sourcing (No `suppliers` Table)**:
  Produce is sourced directly from village farms. Middlemen and third-party supplier entities do not exist in this domain. Consequently, there is no `suppliers` table and no `supplier_id` column on batches.
- **Farmers as Users (No `farmers` Table)**:
  Farmers are account identities represented in the Phase 1 `users` table, assigned the `FARMER` role via `user_roles`. Farm ownership is established via `farms.owner_user_id → users.id`.
- **Product Catalog Decoupling (No `product_id` on `batches` in Phase 2)**:
  Product master catalog entities belong to **Phase 3 (Catalog & Products)**. To avoid loose, unvalidated cross-domain references, `batches` does not define a `product_id` column in Phase 2. When Phase 3 introduces the `products` table, a foreign key (`batches.product_id → products.id`) will be added via migration.
- **Audit Immutability (No `updated_at` on `quality_checks`)**:
  Quality checks record immutable physical inspection events. Once performed and recorded, they represent historical audit evidence.

## 4. Table Specifications

### Table 1: `farms`

#### Purpose
Represents agricultural landholdings and farm properties owned by registered farmers.

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `owner_user_id` | `BIGINT` | No | None | Foreign key referencing `users.id` |
| `name` | `VARCHAR(150)` | No | None | Farm or estate name |
| `address_line_1` | `VARCHAR(255)` | No | None | Farm physical address line 1 |
| `address_line_2` | `VARCHAR(255)` | Yes | `NULL` | Address line 2 / Landmark |
| `village` | `VARCHAR(150)` | No | None | Village name where farm is located |
| `city` | `VARCHAR(100)` | No | None | Nearest city or taluka |
| `district` | `VARCHAR(100)` | Yes | `NULL` | Revenue district |
| `state` | `VARCHAR(100)` | No | None | State / Province |
| `postal_code` | `VARCHAR(20)` | No | None | Postal PIN / ZIP code |
| `latitude` | `NUMERIC(9,6)` | Yes | `NULL` | Geographic latitude (-90.0 to +90.0) |
| `longitude` | `NUMERIC(9,6)` | Yes | `NULL` | Geographic longitude (-180.0 to +180.0) |
| `contact_number` | `VARCHAR(20)` | Yes | `NULL` | Local contact telephone number |
| `status` | `VARCHAR(30)` | No | None | Operational status of the farm |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | Record modification timestamp |

#### Foreign Keys & Delete Behaviors
- `fk_farms_owner_user_id`: References `users.id` with `ON DELETE RESTRICT`. Deleting a user who owns active farm records is prohibited to protect historical traceability.

#### Constraints & Indexes
- **Primary Key**: `pk_farms` on `(id)`
- **Check Constraint**: `ck_farms_status`: `status IN ('ACTIVE', 'INACTIVE', 'SUSPENDED')`
- **Check Constraint**: `ck_farms_latitude`: `latitude IS NULL OR (latitude >= -90.0 AND latitude <= 90.0)`
- **Check Constraint**: `ck_farms_longitude`: `longitude IS NULL OR (longitude >= -180.0 AND longitude <= 180.0)`
- **Indexes**:
  - `ix_farms_owner_user_id` on `(owner_user_id)`
  - `ix_farms_status` on `(status)`

### Table 2: `batches`

#### Purpose
Represents an individual harvest lot of fresh agricultural produce harvested from a specific farm.

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `farm_id` | `BIGINT` | No | None | Foreign key referencing `farms.id` |
| `batch_code` | `VARCHAR(100)` | No | None | Unique human-readable and barcode batch identifier |
| `harvest_date` | `DATE` | No | None | Date of produce harvest |
| `expiry_date` | `DATE` | Yes | `NULL` | Estimated perishable shelf-life expiry date |
| `quantity` | `NUMERIC(12,3)` | No | None | Metric quantity harvested (strictly > 0) |
| `unit` | `VARCHAR(20)` | No | None | Unit of measurement |
| `status` | `VARCHAR(30)` | No | None | Lifecycle stage of the batch |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Record creation timestamp |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | Record modification timestamp |

#### Foreign Keys & Delete Behaviors
- `fk_batches_farm_id`: References `farms.id` with `ON DELETE RESTRICT`. A farm cannot be deleted while batches are linked to it.

#### Constraints & Indexes
- **Primary Key**: `pk_batches` on `(id)`
- **Unique Constraint**: `uq_batches_batch_code` on `(batch_code)`
- **Check Constraint**: `ck_batches_quantity`: `quantity > 0`
- **Check Constraint**: `ck_batches_expiry_date`: `expiry_date IS NULL OR expiry_date >= harvest_date`
- **Check Constraint**: `ck_batches_status`: `status IN ('HARVESTED', 'COLLECTED', 'SORTED', 'GRADED', 'APPROVED', 'REJECTED', 'EXPIRED')`
- **Check Constraint**: `ck_batches_unit`: `unit IN ('KG', 'G', 'L', 'ML', 'UNIT', 'DOZEN', 'BOX', 'CRATE')`
- **Indexes**:
  - `ix_batches_farm_id` on `(farm_id)`
  - `ix_batches_harvest_date` on `(harvest_date)`
  - `ix_batches_status` on `(status)`

### Table 3: `quality_checks`

#### Purpose
Records an inspection and grading event conducted on a harvest batch by an authorized staff member or quality inspector.

#### Columns
| Column Name | PostgreSQL Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | No | Auto-increment | Primary key |
| `batch_id` | `BIGINT` | No | None | Foreign key referencing `batches.id` |
| `checked_by_user_id` | `BIGINT` | No | None | Foreign key referencing `users.id` (inspector) |
| `checked_on` | `TIMESTAMPTZ` | No | None | Timestamp when inspection occurred |
| `status` | `VARCHAR(30)` | No | None | Result of the inspection (`PENDING`, `PASSED`, `FAILED`) |
| `remarks` | `TEXT` | Yes | `NULL` | Quality notes, grading parameters, or rejection reasons |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | Audit creation timestamp |

#### Foreign Keys & Delete Behaviors
- `fk_quality_checks_batch_id`: References `batches.id` with `ON DELETE RESTRICT`.
- `fk_quality_checks_checked_by_user_id`: References `users.id` with `ON DELETE RESTRICT`.
Deleting a batch or user who performed quality inspections is prohibited to preserve audit evidence.

#### Constraints & Indexes
- **Primary Key**: `pk_quality_checks` on `(id)`
- **Check Constraint**: `ck_quality_checks_status`: `status IN ('PENDING', 'PASSED', 'FAILED')`
- **Indexes**:
  - `ix_quality_checks_batch_id` on `(batch_id)`
  - `ix_quality_checks_checked_by_user_id` on `(checked_by_user_id)`
  - `ix_quality_checks_checked_on` on `(checked_on)`
  - `ix_quality_checks_status` on `(status)`

---

## 5. Global Architectural Conventions (Preserved)

- **Primary Keys**: `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- **Timestamps**: `TIMESTAMPTZ NOT NULL DEFAULT now()`
- **Application Level Updates**: `updated_at` on `farms` and `batches` updated at application/ORM level; no database triggers.
- **Identifier Casing**: `snake_case` throughout.
- **Testing**: Executed exclusively against the isolated `gawachabazaar_test` database.
